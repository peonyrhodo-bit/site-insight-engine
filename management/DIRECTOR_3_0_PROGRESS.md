### Результаты разрешённого read-only аудита

Проверен подключённый проект Supabase **site-insight-memory**. Выполнялись только `SELECT`, без чтения значений ключей, миграций и изменения данных.

| Проверка | Результат |
| --- | ---: |
| Строк в `public.director_runs` | 159 |
| Отдельная колонка `idempotency_key` | отсутствует |
| `data_json` | `jsonb` |
| Строк с `data_json.idempotency_key` | 0 |
| Строк с `data_json.idempotency_status` | 0 |
| Строк без `project_id` в колонке | 0 |
| Несовпадений `project_id` в колонке и JSON | 0 |
| Различных проектов | 1 |
| Строк со статусом `requested` или `running` | 1 |

Существуют уникальный индекс одного активного запуска на проект (`status IN ('requested','running')`), первичный ключ и индексы по времени/статусу. Это **снимок на момент аудита**, не гарантия будущих данных. Наличие одной активной строки не означает, что процесс действительно выполняется; состояние не изменялось.

**Блокер:** у экспериментального метода нет явной пагинации, а эквивалентность полной истории и адресного поиска ещё не доказана. До исправления и тестов запрещено использовать пустой ответ кандидатов как доказательство отсутствия повторного запуска.

## PR-C: автономный режим и ручной запуск

- Draft PR: https://github.com/peonyrhodo-bit/site-insight-engine/pull/73
- Ветка: `fix/pr-c-autonomous-mode-gate-20261120`.
- `AUTONOMOUS_ENABLED=false` (по умолчанию) запрещает запуск фонового worker при старте приложения.
- `POST /director/autonomous/run` теперь требует серверный `DIRECTOR_MANUAL_RUN_TOKEN` и заголовок `X-Director-Run-Token`; без настройки или при неверном токене — HTTP 403.
- Тесты прямого вызова и HTTP/ASGI маршрута не выполняют настоящий цикл Директора.
- Документы: [PR_C_MANUAL_API_CLIENT_GUIDE.md](../blob/fix/pr-c-autonomous-mode-gate-20261120/management/PR_C_MANUAL_API_CLIENT_GUIDE.md) (см. также прямую ссылку ниже), [PR_C_RELEASE_COMPATIBILITY.md](../blob/fix/pr-c-autonomous-mode-gate-20261120/management/PR_C_RELEASE_COMPATIBILITY.md).
- Ссылки на исходные документы:
  - https://github.com/peonyrhodo-bit/site-insight-engine/blob/fix/pr-c-autonomous-mode-gate-20261120/management/PR_C_MANUAL_API_CLIENT_GUIDE.md
  - https://github.com/peonyrhodo-bit/site-insight-engine/blob/fix/pr-c-autonomous-mode-gate-20261120/management/PR_C_RELEASE_COMPATIBILITY.md
- **Блокер:** неизвестен полный список внешних клиентов ручного маршрута; внешний ingress/gateway не проверен. Необходимо согласовать секрет, миграцию клиентов и план отката.

## Архитектурные границы

`server.py` — интеграционный HTTP/API слой. Доменная логика остаётся в `memory/`, `research/`, `scheduler/` и связанных компонентах Директора. Цель работ — уменьшить широкие чтения, сохранить семантику исторических данных и исключить несанкционированные/дублирующиеся запуски.

## Приоритетный план

1. **PR-C:** инвентаризировать все вызывающие системы, проверить ingress и авторизацию; согласовать хранение/ротацию токена и проверить совместимость в изолированной среде.
2. **PR-A:** подтвердить корректность адресных чтений на наследуемых данных и измерить нагрузку в изолированной среде.
3. **PR-B:** дополнить адресный поиск гарантированной пагинацией, проверить на fixture все форматы записей, ошибки БД и конкурентные сценарии; затем отдельно согласовать переключение рабочего алгоритма.
4. После ревью каждого PR: согласовать последовательность релизов, критерии остановки и rollback; **merge/deploy только с явного разрешения владельца**.

## Правила безопасности и управления изменениями

- Никаких production deploy, merge, миграций, live-запусков Директора или YouTube-вызовов без отдельного разрешения.
- Read-only аудит Supabase от 2026-11-20 был разрешён владельцем и не менял данные.
- CI показывает прохождение тестов в GitHub, а не готовность внешних клиентов или фактическое поведение production.
- Если требуется проверка, затрагивающая реальные операции, предварительно согласовать её объём с владельцем.
